## Behavioral changes that matter

| Area | Meaningful change | Limitation |
| --- | --- | --- |
| Worker Stop | Current caller/placement authority now reaches the canonical abort effect, closing a stale-authority gap after admission. | Existing protected-run selection and controller drain are preserved; this does not add a new generic process-tree kill. |
| Native approvals | New requests use applied Gateway configuration; each request keeps its admitted config throughout routing/delivery/cleanup. | In-flight approvals deliberately do not jump to a new account after reload. This is channel-native routing, not new spoken approval support. |
| Codex parent stop/yield | Cleanup waits for the exact native turn's interruption before subscription transfer; stopped parents can retain subscriptions for live children and accept later messages. | Stop is not equivalent to killing all children; retained authority stays bound to the original source, binding and lineage. |
| Queued credentials | Caller, service and placement authority are rechecked after queue/preparation waits and at attachment commit admission. | Once committed, caller closure does not undo attachment or excuse cleanup; custody must still settle correctly. |
| ACP approval relay | Raw MCP exec approvals match the originating run ID inside the exact session, falling back to tool-call IDs only without a run ID. | Gateway decision authority remains the source of approval; correlation is corrected, not expanded. |
| Speech permissions | `@Sendable` prevents actor-isolation traps when iOS TCC invokes authorization callbacks on a background queue. | Two iOS source files only; no Linux/macOS speech fix is established. |

### 1. Worker Stop: authority at the effect, not only at entry

Commit [19c3c303faaa](https://github.com/openclaw/openclaw/commit/19c3c303faaa6e17efbbd7dc31757d23db5d5a24) adds one consequential argument: `assertCurrent: request.assertCurrent` to `abortChatRunsForSessionKeyWithPartials` ([server-worker-placement-cancel.ts:17–49](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-worker-placement-cancel.ts#L17)). Existing behavior still selects protected runs under a revalidated resource lifecycle, uses RPC stop origin, snapshots/persists cancellation and waits for matching abort controllers to be removed. The internal admin flag does not authorize the original RPC caller.

The stock `sessions.reclaim` RPC validates its target, reads placement, checks `sessionMutationAuthorization`, and passes that live assertion into placement reclaim ([sessions-dispatch.ts:640–693](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-methods/sessions-dispatch.ts#L640)). `runReclaimPreparation` captures session/lifecycle revision, rechecks caller and exact placement, then `cancelAndDrain` passes that assertion to the cancellation callback ([server-worker-placement-reclaim.ts:119–198](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-worker-placement-reclaim.ts#L119), [228–300](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-worker-placement-reclaim.ts#L228)). Startup wires that callback to the changed helper ([server-runtime-state-prepare.ts:232–239](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-runtime-state-prepare.ts#L232)).

The canonical abort plan invokes the supplied assertions around secondary command cancellation ([chat-abort-session-plan.ts:179–190](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-methods/chat-abort-session-plan.ts#L179), [318–331](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-methods/chat-abort-session-plan.ts#L318)); abort runtime also rechecks before announcing cancellation and settles persistence afterward ([chat-abort-runtime.ts:305–342](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-methods/chat-abort-runtime.ts#L305)). Hence the added argument changes authorization through awaited work. It is not just a signature refactor, nor evidence that speech/transcript interruption kills every real process.

### 2. Native approvals: reload changes future admission

Commit [de6ab4faa223](https://github.com/openclaw/openclaw/commit/de6ab4faa2231ae91de6f0d632169d180427a9cc) captures the owning Gateway runtime at handler creation. Each new request receives current config from that owner; a WeakMap keyed by request payload preserves that context even if normalization replaces the wrapper ([approval-handler-runtime.ts:439–458](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/approval-handler-runtime.ts#L439)). The factory's existing caller runs under `withGatewayNativeApprovalRuntime` ([approval-handler-bootstrap.ts:82–112](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/approval-handler-bootstrap.ts#L82)). Gateway owner closure makes `getRuntimeConfig()` throw ([server-instance-runtime.ts:486–491](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/server-instance-runtime.ts#L486)). Standalone handlers keep `params.cfg`.

`getRequestConfig` now feeds route classification and planned delivery, while availability/policy/presentation/finalization use the same request context ([approval-native-runtime.ts:119–125](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/approval-native-runtime.ts#L119), [199–209](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/approval-native-runtime.ts#L199), [approval-handler-runtime.ts:550–588](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/approval-handler-runtime.ts#L550)). Test account-routing changes on hot reload, old-request cleanup through its original account, owner closure, and standalone handling. Do not interpret this as a universal revocation rule for an already admitted approval.

Related behavior: [5065a187e13a](https://github.com/openclaw/openclaw/commit/5065a187e13ac723cc6f512b231d98feed7bb892) makes canonical SQLite policy authoritative even with retained legacy approvals files. The migration guard is now invoked when no canonical row exists, while malformed canonical rows remain fail-closed ([exec-approvals-sqlite.ts:96–121](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/infra/exec-approvals-sqlite.ts#L96)). This restores operation with a valid canonical policy rather than granting permission from legacy input. Missing canonical policy plus legacy input still requires Doctor; source files are retained for reconciliation.

### 3. Codex: native process custody survives selected parent stops

Commit [11e3514a0ade](https://github.com/openclaw/openclaw/commit/11e3514a0adee8577886e5effc02ce1f404c7e2e) makes `sessions_yield` save/await the exact turn interruption promise before cleanup transfers subscription ownership ([run-attempt-lifecycle-controller.ts:148–158](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt-lifecycle-controller.ts#L148)). The interruption path waits for Codex confirmation; only success records `nativeCancellationConfirmed`, while failure closes the startup client best-effort ([run-attempt-turn-state.ts:99–115](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt-turn-state.ts#L99)). Main run attempts execute cleanup from their teardown path ([run-attempt.ts:125–145](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt.ts#L125)).

Cleanup joins `abortCleanup`; ordinary non-incognito threads can retain subscription after confirmed native cancellation when configuration/native custody requirements hold ([run-attempt-cleanup.ts:69–79](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt-cleanup.ts#L69), [115–136](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt-cleanup.ts#L115)). Retention still checks exact client/thread owner and current original lineage under a lease. Protected live children or admitted native processes permit cleanup authority to outlive foreground cancellation, **not permission to invent new authority after reset/rebinding/revocation** ([run-attempt-resources.ts:393–461](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/run-attempt-resources.ts#L393)). New `assertCleanup` uses retained source authority when available, falling back to active host authority ([native-process-authority.ts:279–329](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/native-process-authority.ts#L279)).

Actual process custody already exists: `cancelTurn` selects commands by exact parent thread+turn; retained-source cancellation terminates admitted processes using their registered `terminate()` callbacks ([native-process-authority.ts:452–492](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/extensions/codex/src/app-server/native-process-authority.ts#L452)). That existing machinery and one-shot CLI terminal cleanup should be regression-tested; the delta primarily corrects safe continuation/retention. Shared-client sibling conversations should remain running. A parent that yielded/stopped can still receive child results under its original lifecycle ([runtime-behavior.md:270–290](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/docs/plugins/codex-harness/runtime-behavior.md#L270)). Do not report parent Stop as “all native children killed.”

### 4. Queued attachment: precommit revocation vs postcommit cleanup

Commit [f54afe6723c0](https://github.com/openclaw/openclaw/commit/f54afe6723c0282dc8d1d0f2f28b263354dc63cc) threads `assertAttachmentCurrent` from placement startup into `environments.attachSession`. It checks request lifetime/authorization plus exact syncing generation, environment and node placement ([placement-dispatch-startup.ts:279–320](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/worker-environments/placement-dispatch-startup.ts#L279)). The broker checks before taking the lock, after store readiness, after installation/build preparation, and through the durable transition ([credential-broker.ts:220–284](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/worker-environments/credential-broker.ts#L220)). Store transition carries caller and placement checks into mutation admission ([store.ts:150–154](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/worker-environments/store.ts#L150), [482–492](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/worker-environments/store.ts#L482)).

Once attachment commits, the broker intentionally deletes pending credentials, stops the old tunnel and stages the exact committed grant without a new caller-authority rejection ([credential-broker.ts:284–292](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/worker-environments/credential-broker.ts#L284)). This distinction prevents both stale queued admissions and abandoned committed cleanup. A deterministic mid-lock/commit race requires the existing regression harness; a fast successful public dispatch alone does not prove it.

### 5. ACP correlation and iOS speech

Commit [3aa32def3bd2](https://github.com/openclaw/openclaw/commit/3aa32def3bd20504b6afff1fda6cafda36dcf9b9) parses raw request run IDs and uses exact session+run matching. Tool IDs remain a fallback only when run ID is absent; ambiguous candidates fail to match ([permission-relay.ts:80–89](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/acp/permission-relay.ts#L80), [translator.agent-events.ts:234–292](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/acp/translator.agent-events.ts#L234)). Commit [641c4d5357c7](https://github.com/openclaw/openclaw/commit/641c4d5357c798c09258e2b8e212744f5f0e4e61) changes only `apps/ios/.../VoicePermissionSupport.swift` and `IOSDeviceSettingsPermissions.swift`: both speech authorization closures are now `@Sendable` ([voice helper:15–23](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/apps/ios/Sources/Voice/VoicePermissionSupport.swift#L15), [settings:50–52](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/apps/ios/Sources/Settings/DeviceSettings/IOSDeviceSettingsPermissions.swift#L50)). The patch fixes a background TCC callback inheriting MainActor isolation; it adds no wake word, hands-free approvals or barge-in, and does not change macOS/Linux callbacks. ## Privacy changes and boundaries

- Active PostgreSQL env SecretRefs, including custom variable names, are registered with the gateway credential filter and cleared/replaced with runtime snapshots ([runtime-state.ts:866–880](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/secrets/runtime-state.ts#L866), [sanitize-env-vars.ts:100–110](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/agents/sandbox/sanitize-env-vars.ts#L100)). Explicit user-owned environment overrides remain possible. Verify inherited host-command and sandbox environments without printing secrets; no claim that all possible child credentials are scrubbed.
- Doctor refuses generated catalog plaintext credentials when the effective local/shared provider auth store already has a SecretRef; it rechecks the effective store within the write lock. Explicit authored literal config keys can still migrate ([doctor-model-catalog-credentials.ts:55–66](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/commands/doctor-model-catalog-credentials.ts#L55), [204–218](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/commands/doctor-model-catalog-credentials.ts#L204)). This is migration behavior, not new login isolation.
- Compaction quotes redact credential-shaped text before clipping. Patterns cover common prefixed keys, JWTs, assignments and private-key blocks; the stored transcript stays raw ([utils.ts:344–370](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/packages/agent-core/src/harness/compaction/utils.ts#L344)). Pattern matching is not a guarantee of removing every secret, and this does not scrub historical transcripts or every model request.
- Paired-node screenshots/photos now use `outbound:false` and explicitly distinguish private model inspection from sending media to the user ([nodes-tool-media.ts:250–265](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/agents/tools/nodes-tool-media.ts#L250), [326–357](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/agents/tools/nodes-tool-media.ts#L326)). Private model context may still leave the device for the configured model; “not automatically attached” is not “fully local.”
- Display history removes private `modelPromptProjection` metadata ([chat-display-projection.sanitize.ts:413–425](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/chat-display-projection.sanitize.ts#L413)). Side chat scopes history/events to authenticated profiles; connections using a shared token without personal identity remain one shared principal ([session-companion-rpc.ts:60–72](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/gateway/session-companion-rpc.ts#L60)).
- Triage exports replace private map keys with opaque numbered identifiers shared only within one archive, with no reversible hash fragment ([diagnostic-support-redaction.ts:95–115](https://github.com/openclaw/openclaw/blob/d843d6af39a42cd3c30084edbeabeece732fd93a/src/logging/diagnostic-support-redaction.ts#L95)). This is improved sanitization, not evidence that telemetry was removed or all diagnostics became anonymous.

## Native rerun matrix and stock interfaces

These are **proposed tests, not performed**. Use disposable candidates and authorized actual services/data according to the lab rules. Avoid synthetic providers when claiming end-to-end results; existing source regression tests can separately exercise deterministic races. No new paid provider is intrinsically required if compatible locally configured backends are already available, but actual Codex/native provider access remains a prerequisite.

| Scenario | Native Linux | Native macOS | Pass evidence |
| --- | --- | --- | --- |
| Gateway/native approvals + reload | Required | Required | New request routes using newly applied account/policy; pre-reload request resolves/cleans up in original target; closed owner admits nothing. |
| Worker Stop while active/queued | Required where worker placement supported | Required where worker placement supported | Exact placement stops, terminal/partial persists, controllers and leases drain, stale caller/changed placement cannot abort unrelated work. |
| Queued credential attach + cancellation | Required with real worker provider | Same if macOS hosts this path | Precommit revocation leaves no new grant; postcommit closure still settles exact attachment/tunnel custody and cleanup. |
| Codex parent Stop/yield with live child + sibling chat | Required | Required | Exact parent interruption confirms before next turn; child result arrives once under original lifecycle; unrelated chat continues; reset/rebind/revoke cannot inherit authority. |
| Native foreground/background shell custody | Required | Required | Owned command stops when appropriate, process inventory agrees; legitimate retained child work continues, one-shot CLI leaves no background terminal; no blanket client shutdown. |
| ACP MCP execution approval | Required | Required | Correct pending run gets prompt despite mismatched MCP/streamed call IDs; approve/deny propagates once; other run never receives it. |
| Privacy and canonical approval policy | Required | Required | Private media isn't auto-sent, profiles don't share Side chat, display omits prompt projection, triage/compaction redact test markers, canonical policy wins. |
| Speech permission callback fix | Not applicable | Not applicable to macOS app | Run on iOS: fresh authorization Allow/Deny and Settings speech request do not crash; cancellation/stale Settings lifecycle remains safe. |

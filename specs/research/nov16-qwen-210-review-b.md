Voice permission handling selects a real pending authorization and submits it to task operations; importantly it announces **local submission before backend acknowledgment** and reports asynchronous delivery failures separately ([agent-task-runtime.mjs:574–613](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/agent-task-runtime.mjs#L574-L613)). ## Permission and credential audit

- Default backend permission mode is **native**, not full ([config.mjs:182–198](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/core/config.mjs#L182-L198)); that delegates initial permission behavior to the backend's configuration. Gateway session policy begins at ask ([permission-policy.mjs:47–59](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/task/permission-policy.mjs#L47-L59)). It cannot force a backend to request permissions for operations its native policy already allows.
- Ordinary affirmative speech is documented in the actual tool schema as `task`: **current task plus future operations**, not one operation. `always` authorizes subsequent permissions across the voice session ([agent-task-tools.mjs:84–100](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/features/agent-task-tools.mjs#L84-L100)); policy implements those grants and auto-approval ([permission-policy.mjs:66–135](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/task/permission-policy.mjs#L66-L135)). This is consequential approval breadth.
- Pi declares always-full permission regardless of requested mode ([catalog.mjs:361–368](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/backend/catalog.mjs#L361-L368), [effective mode:544–548](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/backend/catalog.mjs#L544-L548)). Explicit full mode enables Codex `agent-full-access` ([codex.mjs:53–55](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/codex.mjs#L53-L55)) and Qoder skip-permissions ([local-acp.mjs:47–51](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/local-acp.mjs#L47-L51)). Internal session-management tools are automatically approved by the broker even in native mode (broker lines 112–123 above).
- Backend authentication is the real coding tool's login/API configuration. It is not supplied by a voice API key: Qwen Code onboarding invokes its own auth ([catalog.mjs:120–128](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/backend/catalog.mjs#L120-L128)); Codex launches its adapter and preserves backend environment ([codex.mjs:29–56](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/codex.mjs#L29-L56)). Environment projection allowlists system context and per-backend names/prefixes rather than inheriting every gateway secret ([environment.mjs:3–47,75–102](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/backend/environment.mjs#L3-L102)). HOME remains available, so existing native login state can be used; this is not a sandbox isolating agents from the user's filesystem/auth.

## Providers, no-paid-key local possibilities, and Linux

Default speech is DashScope, with external realtime audio transport. Catalog includes StepFun, GPT/OpenAI Realtime, Google Live, Doubao, local speech-to-speech and MiniCPM-o endpoints ([provider definitions:6–75](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/realtime-provider-definitions.mjs#L6-L75)). Credential-vs-endpoint configuration requirements are enforced by the selected provider ([runtime-configuration.mjs:7–21](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/runtime-configuration.mjs#L7-L21)).

**Stock local possibility, with an external service to supply:** choose `QWEN_AUDIO_REALTIME_PROVIDER=speech-to-speech` and `QWEN_AUDIO_REALTIME_URL=ws://127.0.0.1:8765/v1/realtime`. Its optional Bearer key can be empty, and the adapter uses OpenAI **Realtime GA WebSocket** semantics, 16k input/24k output, tools and VAD ([s2s.mjs:28–99](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/s2s.mjs#L28-L99)). User-managed speech-to-speech owns ASR/LLM/TTS/model/voice choices. Qwen does not launch/provision that model stack. Generic OpenAI-compatible `/audio/transcriptions` plus `/audio/speech` HTTP servers alone do **not** satisfy this contract. GPT-live also allows a configurable URL but requires a nonempty credential and applies its provider model/schema assumptions ([gpt-live.mjs:24–60](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/gpt-live.mjs#L24-L60)).

**Ollama inference:** no native Ollama implementation was found in the runtime source search. The stock `llm` backend is an HTTP chat-completions adapter: set `AGENT_PROTOCOL=llm`, `QWEN_AUDIO_AGENT_LLM_BASE_URL=http://127.0.0.1:11434/v1`, a local model via `QWEN_AUDIO_AGENT_BACKEND_MODEL`, and a nonempty dummy `QWEN_AUDIO_AGENT_LLM_API_KEY=ollama` if the local endpoint ignores auth. Config accepts generic endpoint/key ([config.mjs:430–443](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/core/config.mjs#L430-L443)); adapter appends `/chat/completions` ([llm backend:43](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L43)), refuses an empty key ([147–157](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L147-L157)), and sends model/messages, `stream:false`, Bearer auth and an abort signal ([263–277](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L263-L277)). This is a plausible no-paid-key local **text task** path, not a verified Ollama integration, audio solution, or tool-executing agent: that request contains no tools/tool loop. Full coding oversight needs an actual configured agent backend (which might separately use a local model).

Linux entrypoints are Node CLI `qwenaudio gateway`, `qwenaudio webui`, and `qwenaudio tui` ([launcher.mjs:65–85](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/cli/src/launcher.mjs#L65-L85), [arguments.mjs:437–438](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/cli/src/arguments.mjs#L437-L438)). ## Material decision points

1. All four requested capability families have substantive implementation at this exact release, deserving 2 each under a source-capability rubric.
2. Approval semantics are broader than per-operation approval; native backend policy and Pi's always-full behavior matter.
3. Executing-task cancel is real ACP cancellation, backend-confirmed where possible, with uncertain-state errors on timeout; it cannot undo prior side effects.
4. Local speech is supported through an externally managed realtime endpoint, not an included speech model installation. Stock local Ollama text use is only an inferred compatibility path and supplies no coding tools.
5. Linux has CLI/browser/TUI and source-built desktop paths, with no Linux binary asset in this release.
6. Actual speech quality, wake reliability, tool selection, backend compatibility, cancellation of a real shell task, and local Ollama/speech interoperability remain untested by design.

# OpenDots with the existing OSS voice stack — 2026-10-05

**Historical run; superseded by the [2026-10-06 service/integration audit](../integration-audit/README.md).** That audit fixes our shared-service and adapter defects and verifies continuous voice, failure recovery and durable conversation history. Physical-phone qualification is outside the requested scope. The project remains on the Watch List as a custom adaptation.

Reusing the lab's hosted open-source speech stack works: OpenDots can receive microphone speech, speak replies, and delegate a spoken request to its real compute agent. This is an adapted build, not evidence that stock OpenDots works without CopilotKit Intelligence or OpenAI voice configuration.

## Changes required

The patch is more than a URL substitution:

1. Opt-in `OPENDOTS_LOCAL_RUNTIME=1` selects CopilotKit's OSS `InMemoryAgentRunner`, binds conversations locally, and routes compute/history/page access through that runner. The original DotAgent and permission-scoped tools still execute the work.
2. `VOICE_BASE_URL` points calls at the existing host. `VOICE_PROTOCOL=speech-to-speech` sends raw SDP, configures instructions/tools through `session.update`, and uses DELETE for remote hangup. The default OpenAI multipart/POST-hangup behavior remains intact.
3. Local server turns initialize the agent's thread, messages, and state. After voice compute and hangup, the browser loads the authoritative message snapshot and converts REST tool calls into AG-UI format. This preserves same-conversation text follow-up without replaying old deltas.
4. Two added unit tests cover the voice handshake/hangup contract and history/tool-call conversion. The adapted build has 184 passing tests across 38 files, plus passing build, typecheck and lint. Unit fixtures are separate from the live evidence.

**This is a test adapter, not a production Intelligence replacement.** Agent message history is bounded and in memory; a server restart loses it. Pages, conversation metadata and call receipts remain in SQLite. Durable scheduling/history, Slack Channels, learning, computer control and multi-agent orchestration were not qualified. Some setup/status strings still use the upstream “Intelligence” label even in local mode; that is not evidence of an Intelligence connection. External access would also need appropriate HTTPS/authentication and WebRTC network configuration.

## What the initial failures taught us

The first harness attempt used a too-specific sidebar selector. A later attempt used empty WAV files generated by sandboxed macOS speech. Another supplied no continuous silence after a sound finished, preventing the speech pipeline from closing the turn. Those are harness failures, corrected before evaluating behavior.

The first local compute/receipt attempt failed because the adapter did not initialize the agent's actual thread state. The first history-refresh attempt replayed old events and duplicated tool-call arguments. Switching to a snapshot initially exposed a REST/AG-UI format mismatch and crashed the tool renderer. Those were adapter bugs, not stock-project findings; the retained patch fixes them and adds conversion coverage. Do not count the earlier failed text follow-up as a pass.

The first interruption attempt triggered on a transcript delta before proving that speech was playing. It produced a cancelled-response event, but the subsequent spoken answer repeated the full count before answering “Paris.” That is not a successful audible barge-in test. The final harness instead waits for measured incoming audio before interrupting.

## Reproduce the adaptation

Apply the patch to the exact upstream pin, then install its lockfile:

```sh
git checkout 71efd82cd883df7b107d663bd36435a1d8a2d12a
git apply /path/to/local-runtime-voice.patch
npm ci
npm run build
npm run typecheck
npm run lint
npm test -- --maxWorkers=1
```

Example environment for the app (the addresses must match the deployment):

```dotenv
OPENDOTS_LOCAL_RUNTIME=1
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_API_KEY=sk-local-dummy
OPENAI_MODEL=qwen2.5:7b-instruct-q4_K_M
VOICE_PROTOCOL=speech-to-speech
VOICE_BASE_URL=http://VOICE_HOST:18765
VOICE_API_KEY=sk-local-dummy
VOICE_MODEL=qwen2.5:7b-instruct-q4_K_M
VOICE_NAME=af_heart
WEB_SEARCH_PROVIDER=disabled
PORT=14310
DATABASE_PATH=/home/tester/evidence/app.sqlite
DO_NOT_TRACK=1
```

Run `npm start`. In this deployment Ollama's guest-loopback endpoint is an SSH reverse tunnel to Orca; speech WebRTC uses the private LAN directly. Port 18765 was chosen because 8765 belonged to another service, which was left alone. The existing speech service is started with:

```sh
VOICE_HOME=/path/to/existing/voice-server \
VOICE_HOST=ORCA_LAN_IP VOICE_RT_PORT=18765 VOICE_OFFLINE=1 \
/path/to/awesome-jarvis/lab/voice-server/voicectl start realtime
```

The [first-call harness](opendots-live.mjs), [follow-up harness](opendots-followup.mjs), and [final harness](opendots-verified.mjs) contain the exact UI actions. Their paths are specific to this disposable guest. Install Playwright Chromium there and provide the `opendots-*.wav` test phrases used in the logs. The [transcription helper](transcribe-opendots.py) uses the already-installed MLX environment and cached Parakeet model, writing coarse 20-second transcript segments; these are not precise word-timing measurements.

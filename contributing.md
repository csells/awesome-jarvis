# Contribution Guidelines

Thanks for helping make this list better. Please make sure your pull request meets these guidelines:

- **One suggestion per pull request.** Search previous suggestions before making a new one to avoid duplicates.
- **It has to serve the hallmarks:** voice, hands-free operation (including spoken approvals and cancel), a visual presence that shows state and work, and oversight of other agents. Jarvis Agents must be strong on at least two of voice, visual presence and oversight, including voice or oversight. Mission Control entries must be strong on oversight. Building blocks must clearly help deliver one pillar. General AI tools with no assistant angle belong in other lists.
- **Show evidence, not marketing.** Link the code files, docs or demo that prove each pillar you claim, and propose a scorecard row, including its "Watch out" caveats, for new Jarvis Agents. Claims that exist only in a README will be checked against the code.
- **Disclose risks.** Say whether the project turns off coding-agent permission checks, sends telemetry, needs a paid cloud service, or uses a non-commercial license.
- **Young projects start on the Watch List.** They graduate once they show sustained activity and more than one maintainer.
- **It's maintained.** Repositories should have commits within the last year and must not be archived. Retired projects of historical importance go in [history.md](history.md).
- **It's good.** This is a curation, not a directory. Explain in the pull request why it belongs, for example by comparison with what's already listed.
- **Format.** `- [Name](link) - Description.` The description starts with a capital letter, ends with a period, and says what makes the project useful for a Jarvis, such as offline, low-latency, open hardware or memory. Skip marketing language.
- **Placement.** Add it to the end of the right category. Propose a new category in an issue first.
- **Lint.** Run `npx awesome-lint` and fix any errors.
- Keep the wording and style consistent with the rest of the list.
- Check your spelling and grammar.

Hands-on test results are especially welcome; say what you ran, on what, and attach transcripts or screenshots.

Found a broken link, a project that has been archived or renamed, or a claim that is out of date? Please open an issue or a pull request. Those fixes are just as valuable as new entries.

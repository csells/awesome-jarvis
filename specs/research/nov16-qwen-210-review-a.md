## Voice and wake chain

The browser microphone capture branches between wake-only 16 kHz audio and normal streaming in [useRealtimeVoice.js:936–1004](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/web/src/realtime/useRealtimeVoice.js#L936). The desktop IPC receives wake audio only from its own hidden main window, validates the sample rate and payload size, and passes it to a worker; detection calls `desktopPresence.wake('wake-word')` ([main.mjs:211–229](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/src/main.mjs#L211)). The worker-backed runtime is real, not a UI placeholder ([runtime.mjs:14–38](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/src/wake-word/runtime.mjs#L14)); sherpa keyword spotting uses CPU ONNX models and consumes PCM samples ([sherpa-detector.mjs:19–50,65–77](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/src/wake-word/sherpa-detector.mjs#L19)). The model manager downloads a specific SHA256-pinned model archive from GitHub ([model-manager.mjs:17–26](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/src/wake-word/model-manager.mjs#L17)). Wake word defaults to false; desktop defaults also select no backend and a 60-second hide interval ([settings-config.mjs:23–35](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/src/settings-config.mjs#L23)). Thus “always listening” requires microphone permission and active voice/wake configuration; it is not an unconditional boot-time behavior.

For barge-in, provider `input_audio_buffer.speech_started` begins a new turn, dismisses announcements, emits `PLAYBACK_CLEAR`, marks listening, then calls **frontend** `cancel()` ([realtime-input-runtime.mjs:77–130](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/realtime-input-runtime.mjs#L77)). Browser playback clears on interruption ([useRealtimeVoice.js:684–696](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/web/src/realtime/useRealtimeVoice.js#L684)). This stops speech/turn generation; it does **not** cancel backend tasks. The local speech-to-speech provider negotiates audio output and `server_vad` with `interrupt_response: true` ([s2s.mjs:70–98](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/s2s.mjs#L70)).

Linux/Windows TUI documentation explicitly states that its Python sounddevice/PortAudio bridge pauses the microphone during playback and uses `/interrupt`; that mode does not provide spoken barge-in ([tui.md:60–68](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/docs/getting-started/tui.md#L60), source default [portaudio-voice-io.mjs:11](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/tui/src/portaudio-voice-io.mjs#L11)). Use the browser/Electron path when evaluating Linux full-duplex behavior; acoustic echo handling still needs an actual test.

## Spoken decisions, dispatch and real cancellation

Realtime function-call completion is handed to `toolCalls.handle`, including correlated turn context ([realtime-session-runtime.mjs:618–636](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/realtime-session-runtime.mjs#L618)). The registered agent tool handlers include `spawn_thinking`, `cancel_agent_task`, status/update and `respond_permission` ([agent-task-tools.mjs:105–127](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/features/agent-task-tools.mjs#L105)). `respond_permission` is exposed only when `permissionPending` supplies `permission.respond` ([frontend-tool-context.mjs:19–36](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/frontend-tool-context.mjs#L19)). The local S2S profile actually supplies these schemas to the model ([s2s.mjs:73–80](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/s2s.mjs#L73)).

Permissions are interpreted from natural speech by the selected model, not a deterministic approval keyword parser. The tool schema instructs clarification when ambiguous and defines `task`, `always`, `reject`: ordinary affirmation selects `task`, allowing the current task's later operations; only explicit instruction should choose session-wide `always` ([agent-task-tools.mjs:81–100](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/features/agent-task-tools.mjs#L81)). Runtime requires a valid decision plus a nonempty current-turn transcript, handles replay, refuses ambiguous multiple pending requests without an ID, revalidates the request, and calls `submitPermission` ([agent-task-runtime.mjs:462–595](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/agent-task-runtime.mjs#L462)). **The guard establishes transcript presence, not independently verified semantic consent.** The model chooses the decision.

Gateway policy defaults to `ask`, stores task/session grants, and maps these to per-operation backend decisions ([permission-policy.mjs:47–77](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/task/permission-policy.mjs#L47), [permission-decisions.mjs:1–7](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/shared/permission-decisions.mjs#L1)). A positive response approves all currently pending requests **for the same task**, not just the visible request, and future policy grants continue the task ([task-operations.mjs:217–242](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/orchestration/task-operations.mjs#L217)). ACP maps allow/reject decisions to actual offered opaque ACP options ([permission-broker.mjs:88–100](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/permission-broker.mjs#L88)).

Dispatch creates a Task whose runner calls the backend runtime and whose canceler calls `backendRuntime.cancel` before aborting local execution ([task-operations.mjs:60–80](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/orchestration/task-operations.mjs#L60)). ACP has independent list/start/send/status/cancel session tools ([session-tools.mjs:10–17](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/session-tools.mjs#L10)); the adapter binds them to concrete session/delegation methods ([backend-adapter.mjs:1027–1037](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/backend-adapter.mjs#L1027)). Codex/Claude driver flags advertise delegation and permissions but `backendUi: false`; Pi advertises neither delegation nor permissions ([Codex driver:6–18](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/codex.mjs#L6), [Claude driver:4–17](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/claude.mjs#L4), [Pi driver:4–16](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/drivers/pi.mjs#L4)).

Spoken cancellation's handler selects explicit/recent/all-session tasks and invokes `taskOperations.cancel`; a single cancellation only reports success when task status is cancelled ([agent-task-runtime.mjs:655–748](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/frontend/tools/agent-task-runtime.mjs#L655)). The TaskManager enters `cancelling`, awaits its canceler and reports failure when cancellation throws ([task-manager.mjs:906–972](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/task/task-manager.mjs#L906)). ACP aborts the owning work and cancels each delegation, invoking native cancellation or `client.cancelSession`; its top-level cancel waits for settlement with timeout ([backend-adapter.mjs:1003–1018](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/backend-adapter.mjs#L1003), [1896–1960](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/backend-adapter.mjs#L1896)). The process client sends ACP `session/cancel`, keeps the prompt RPC alive for terminal confirmation, and marks context uncertain if it times out ([process-client.mjs:658–695](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/acp/process-client.mjs#L658)). This is real remote cancellation, **not OS process-tree killing or a guarantee that shell grandchildren stop**. Test actual backend behavior before claiming that guarantee. LLM-only cancellation aborts HTTP fetch; it cannot prove a remote inference server stopped compute ([LLM adapter:263–277,347–358](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L263)). A2A calls remote `cancelTask`, but explicitly does not implement authorization decisions ([A2A adapter:1131–1159](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/a2a/backend-adapter.mjs#L1131)).

## Local models and Linux feasibility

1. **Text backend:** `AGENT_PROTOCOL=llm`, model via `QWEN_AUDIO_AGENT_BACKEND_MODEL`, and `QWEN_AUDIO_AGENT_LLM_BASE_URL=http://127.0.0.1:11434/v1` can target an Ollama OpenAI-compatible endpoint. Configuration accepts those overrides ([config.mjs:108–132,430–446](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/core/config.mjs#L430)); the adapter POSTs model/messages to chat completions without streaming or tools ([LLM adapter:263–277](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L263)). It requires a nonempty API-key string even for unauthenticated local services ([LLM adapter:107,147–165](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/backend/adapters/llm/backend-adapter.mjs#L107)); a dummy local token is therefore needed. **Compatibility is inferred from the implemented API contract, not tested against Ollama here.** This backend cannot execute coding tools or provide approvals, so it cannot validate the full oversight score.
2. **Speech:** Ollama's ordinary chat endpoint is insufficient for the voice frontend; Qwen Audio needs a compatible realtime WebSocket service. Its S2S adapter owns no local STT/TTS model; the external service owns VAD/STT/LLM/TTS and can run fully locally with optional bearer auth ([s2s.mjs:28–67](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/s2s.mjs#L28)). First-party setup documents Linux CUDA, smaller CPU models and local vLLM/llama.cpp endpoints; one Chinese Qwen3-TTS recipe requires a specifically pinned upstream fix ([speech-to-speech.md:16–90](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/docs/voice-frontends/speech-to-speech.md#L16)). An S2S-to-Ollama configuration is plausible but not independently established from this repository's code.
3. **MiniCPM-o:** local endpoint and audio/video exist, but `functionCalling:false`, `conversationItems:false`, `clientResponses:false`, `mutableSession:false` mean it is unsuitable as evidence of spoken dispatch/approval parity ([minicpm-o.mjs:9–16,67–92](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/src/voice/providers/minicpm-o.mjs#L9)).
4. Source/CLI prerequisites are Node `^22.22.2 || ^24.15.0 || >=26.0.0`, npm >=10 ([package.json:248–251](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/package.json#L248)). Electron Linux AppImage/deb build is defined; config comments say official release desktop artifacts are macOS/Windows and Linux is self-built ([electron-builder.yml:67–76](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/desktop/electron-builder.yml#L67)). Browser voice needs working microphone/speaker permissions and a secure browser context for remote access. TUI additionally needs Python/sounddevice/PortAudio as above. No Linux GUI/audio runtime or hardware latency has been validated here.

## Proposed native Linux tests with no paid API keys (not run)

- Run existing Node suites in a disposable test environment: `node --test server/test/realtime-input-runtime.test.mjs server/test/permission-policy.test.mjs server/test/task-operations.test.mjs server/test/task-manager.test.mjs server/test/llm-backend-adapter.test.mjs`; then provider, WebUI task/permission rendering and desktop wake-runtime tests after their dependencies are available. The LLM tests inject a fake fetch and cancellation signal rather than needing a paid provider ([llm-backend-adapter.test.mjs:20–49](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/test/llm-backend-adapter.test.mjs#L20)); input tests use an explicit frontend harness ([realtime-input-runtime.test.mjs:8–38](https://github.com/QwenAudio/qwen-audio-agent/blob/a9f4478da8df400d04facbb099ac2933ce8b11bc/server/test/realtime-input-runtime.test.mjs#L8)). These prove contracts, not actual speech understanding.
- With local Ollama and the LLM backend, submit a long text task, see status/results in the browser, cancel it, and observe HTTP disconnect plus remote server behavior separately. Verify empty-key rejection and dummy-key adoption. Do not label this a coding-agent approval test.
- Run local S2S on Linux and record spoken response, audio/transcript alignment, repeated barge-in, ambient-noise behavior and latency. Use browser/Electron instead of default Linux TUI. With a locally configured permission-capable coding backend, test spoken grant/reject/ambiguous response, later same-task permission auto-grants, concurrent requests, and cancellation while working or waiting for permission. Availability depends on a local model that can reliably call the exposed functions; no paid key is inherently required, but model/hardware/backend prerequisites remain.
- For the worker-stop test, use an authorized harmless long-running operation that emits timestamps; speak cancel and verify the **actual worker and its child process** stop, while barge-in alone leaves it running. Check uncooperative ACP timeout handling and that no successful cancellation receipt appears early. Existing source wiring cannot substitute for this test.
- Build/run Linux Electron and enable wake word; hide it, say the configured phrase, inspect local microphone/network behavior, wake back into voice mode and check barge-in. Also test browser rendering under Xvfb separately from real audio; virtual display alone cannot establish microphone/acoustic behavior.

Remaining uncertainty: no installation, existing tests, real audio, Ollama protocol interaction, live ACP cancellation or Linux packaging was exercised. The strongest source finding is that complete orchestration paths exist; the biggest practical gates are provider/backend capability combinations, model-dependent consent interpretation, task-wide approval semantics, and whether real subprocesses obey cancellation.

# Real build evaluation of build-jarvis

Status: complete for the bounded evaluation, November17,2026 UTC. The earlier response-only scenarios checked interpretation and scope, not whether the skill can guide a working build. After the user challenged that validation, a fresh agent used the skill to implement and run a small candidate in an owned disposable Linux VM against real shared model and speech services. The parent independently exercised the resulting artifact.

## Acceptance

- Candidate code runs only in the disposable guest. Stable services/configuration remain unchanged; no host login copying, paid keys or phone calls.
- Real native browser UI, microphone capture and speaker output; independent recorded input/output controls and ASR.
- Actual factual voice reply and acoustic interruption/new question while verified speech plays.
- Real backend-gated scratch-file action: pending state, deny and approve with independently inspected effects; distinguish spoken from clicked control.
- Actual bounded worker and visible progress while conversation continues. Cancel verified against process identity and heartbeat; distinguish native Stop from harness cleanup.
- Remember a harmless fact and verify retrieval after actual candidate restart. Verify fresh work/approval after cancellation and replay handling where implemented.
- Exercise at least two actual sessions, including restart/recovery. Keep failed/invalid attempts and patches as evidence.
- Preserve source and sanitized results outside the guest; inspect UI screenshots and exact effects. Stop owned jobs/browser/audio/forwards, remove leased keys and release the shared-service reservation, then stop the guest.

The independent builder receives user requirements, the skill and operational interfaces, rather than an implementation from the skill author. Its self-reported passes do not substitute for the parent tests. A bounded task worker does not certify autonomous coding-agent orchestration; virtual audio does not certify physical room/phone behavior. This is evaluation infrastructure, not authorization to promote a new persistent Jarvis service.

Use observed failures to revise the skill and repeat the affected real flow. Retain the original smoke-test results as limited evidence; do not describe them as functional build validation or claim a measured improvement over a no-skill implementation.

## Outcome

[Live evaluation](../../research/build-jarvis-live-evaluation.md) records23 actual audio attempts and the independently checked effects. Native voice/repeated interruption, spoken denial/approval and replay controls, real worker progress/conversation/cancellation twice, memory across actual restart and the final UI callback regression were exercised. The initial container failure, interrupt race, clipped/unrecognized speech, v4 intermittent failure, repeated-denial routing defect and stale playback-error banner remain recorded alongside repairs. Relevant lessons were added to the portable skill references.

Source versions and raw evidence were exported and hash-verified outside the VM; credential-value scans passed before deleting the controller lease copy. Owned runtime/audio/profile/forwards were removed, Pocket released and ready, guest ports closed and the correctly identified VM stopped. Registry revision20 records completion, retained guest owner and review expiry. [Sanitized artifacts](../../../lab/evidence/build-jarvis-skill-2026-11-17/README.md) preserve exact observed scope and cleanup.

Physical acoustics, autonomous coding workers, multi-user authority, crash recovery and soak/outage paths remain outside this bounded evaluation. No service promotion or main-branch publication was authorized or performed. This closes the evaluation plan, not those unexecuted product qualification cases.

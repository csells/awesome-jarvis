# Paseo 0.15.4 → 0.16.0: source delta

Source/setup evidence only. Later native outcomes and superseding qualifications are recorded in the [release follow-up](../../lab/evidence/reverification-2026-11-12/nov16/README.md#release-follow-up).

Inspected 2026-11-16. This is a source investigation, not a runtime qualification or installation recommendation. No candidate was installed, executed, authenticated, or connected to the lab.

## Versions and coverage

- Baseline: `v0.15.4` = `1c00b365c9e0b74c1580eba33d905d693125ae21` ([release](https://github.com/getpaseo/paseo/releases/tag/v0.15.4)).
- Candidate: `v0.16.0` = `c54bc39e7997c03a07402c09df2e825889432557` ([release](https://github.com/getpaseo/paseo/releases/tag/v0.16.0)).
- A local Git clone at `/private/tmp/paseo-delta-source-20261116` supplied both exact trees and the full Git diff: 329 commits; 1,709 files; 124,351 added and 22,622 deleted lines. The changed-path inventory is `/private/tmp/paseo-delta-files.txt`. This did not use GitHub's truncated compare-file API.
- All changed paths were inventoried, server changes were searched for the requested behaviors, and relevant runtime implementations and selected tests were read. This is **not** a line-by-line audit of every unrelated change in the 1,709 files. Full source access succeeded; behavioral verification remains absent. No other reviewers' research was used.

## Main finding

0.16.0 does not replace the voice architecture or add an OpenAI Realtime voice conversation path. The only changed implementation under the speech-provider directory is a local-provider configuration fix: keep local runtime configuration when local turn detection is enabled, even when all STT/TTS use sites select OpenAI. Most relevant change is around Codex process lifecycle, background work, provider options, and client reconnection. Existing voice capability claims must be carried forward as unverified until tested on the exact candidate.

## Voice path: changed configuration, largely unchanged implementation

`speech/providers/local/config.ts::shouldIncludeLocalProviderConfig` now includes enabled `voiceTurnDetection` using local. Before this, remote STT/TTS plus local VAD could omit local runtime configuration. This is a concrete prerequisite fix for an OpenAI-compatible speech server with local turn detection; it does not establish compatibility with any particular server. [Exact source](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/speech/providers/local/config.ts#L78)

Git comparison confirms zero changes across `session/voice/`, `speech/providers/openai/`, `voice-config.ts`, `voice-permission-policy.ts`, and `agent/runtime-mcp-config.ts`. Their actual call chain remains:

1. `VoiceSession.startVoiceTurnController` resolves local turn detection and STT, then `onSpeechStarted` invokes `handleVoiceSpeechStart`. Confirmed VAD speech aborts playback and the active agent run before transcription finishes. `handleAbort` aborts the shared controller, cancels pending playbacks, and calls host `interruptAgentIfRunning`; during transcription it preserves that phase and buffers subsequent audio. [Voice implementation](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session/voice/voice-session.ts#L562)
2. Final STT output goes through `sendSpokenInput`, `Session.sendMessageToAgent`, and `wrapSpokenInput`. Prompt instructions require `speak` for user-facing communication and acknowledgement before other tools. This is prompt guidance, not a restriction of the agent's general tool authority. [Prompt](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/voice-config.ts#L1), [session](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session.ts#L4493)
3. Voice bridge registration associates the active agent with a `speak` handler and `enableVoiceTools`. `paseo-tools.ts` exposes `speak` only for an enabled caller context (or explicit voice options); requires an agent-scoped caller; accepts at most 4,000 characters; resolves that caller's handler; passes cancellation signal; and blocks until playback completes. The session combines the MCP cancellation signal with its own abort signal and calls `generateAndWaitForPlayback`. [Tool](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/tools/paseo-tools.ts#L1329), [playback bridge](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session/voice/voice-session.ts#L1053)
4. Runtime Paseo MCP is injected as HTTP `/mcp/agents?callerAgentId=...` with a capability bearer header when configured. A preexisting user `paseo` MCP entry prevents replacement. Voice tool registration is dynamic in the caller context, not a new independent speech account or transport. [Injection](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/runtime-mcp-config.ts#L39)

### Provider-specific limits

- Speech provider selection remains `local` or `openai`; Ollama is not a direct STT/TTS provider. For speech, an Ollama/Pocket-associated deployment must expose the OpenAI-compatible audio endpoints; ordinary chat completion compatibility is insufficient. `OpenAISTT` buffers 24 kHz mono PCM, commits WAV to `audio.transcriptions.create`, and receives final transcripts. It is not a Realtime WebSocket API client. [STT](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/speech/providers/openai/stt.ts#L63)
- `resolveOpenAiSpeechConfig` permits independent STT/TTS base URLs, arbitrary model IDs, and custom TTS voice IDs, but requires a nonempty API key to build each config. A compatible service that ignores authentication still needs a nonsecret placeholder in an isolated test config. TTS explicitly requests PCM. Verify output really is the expected raw PCM, rather than an endpoint returning WAV/MP3 under that request. [Config](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/speech/providers/openai/config.ts#L37)
- `OpenAITTS.synthesizeSpeech` downloads the entire response into `arrayBuffer()` before exposing a readable stream. Playback may be chunked afterward, but network synthesis is not streamed into playback as bytes arrive. Cancellation of playback does not prove upstream synthesis stops: this method supplies no abort signal to `audio.speech.create`. This is unchanged, not a new regression. [TTS](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/speech/providers/openai/tts.ts#L45)
- Official Codex CLI authentication supplies the agent provider, not OpenAI speech credentials. It can be paired with local ONNX speech or a separately configured compatible audio server. The source comments target Codex config 0.143+, but that alone is not a tested minimum version for every background-terminal RPC. [Codex options](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex/options.ts#L37)

## Permissions and cards

The voice auto-approval predicate is unchanged: only `kind: tool` with a normalized direct speak-tool name is automatically allowed. Wrapper tools merely mentioning `speak` are not allowed by this predicate. `Session` applies it only to voice-active agents. It does **not** make other tools automatically denied: they follow provider policy and ordinary permission handling. [Predicate](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/voice-permission-policy.ts#L4), [call site](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session.ts#L2185)

Codex options now unify `service_tier` and `plan_mode` with provider options. `applyOptions` explicitly permits those two live controls, while approval policy and sandbox changes are rejected for an already-running session because they are sent at thread startup. An unavailable speed on model switch resets to explicit Normal/default and emits `options_changed`, preventing it returning unexpectedly later. Profiles migrate legacy `featureValues` to `options` with a compatibility wire representation. Re-test persisted profiles and changing permission mode on an existing agent; a saved UI selection is not proof that its running sandbox changed. [Live option application](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L4909), [migration](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/daemon-config-store.ts#L175)

The changed `QuestionFormCard` makes clicking an option description select the option (links remain separate), ignores repeat clicks, and removes automatic advance after a single-select choice. This is a question card change, not evidence of a new permission-policy enforcement layer. OpenCode v2 now forwards a deny message and reads `auto_accept` from `providerOptions`. [Question card](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/app/src/components/question-form-card.tsx#L43), [OpenCode](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/opencode/v2/permissions.ts#L60)

## Codex cancellation and background work

Previously `turn/interrupt` could leave its shell processes alive. The candidate records root-thread `commandExecution` process IDs by native turn ID. After accepted interrupt it issues **per-process** `thread/backgroundTerminals/terminate`, including commands observed late. It does not call broad thread cleanup, preserving earlier completed turns' intentional background processes and excluding child-thread commands. New turn startup waits for the cleanup promise, bounded to 4.5 seconds; terminate RPCs have 2-second bounds; at most 16 turns are retained. [Implementation](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L5303), [tracking and bounds](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L5370)

**Limit:** cleanup failures warn and do not fail the next turn; IDs are marked terminated before the RPC finishes, so that ID is not retried by a later sweep. Therefore interruption is best-effort process cleanup, not a guarantee all processes have died. Missing process IDs, unsupported RPCs, detached grandchildren, and timed-out requests require runtime testing. No confirmed runtime regression was established here.

New Codex background inventory paginates `thread/backgroundTerminals/list`, hides commands belonging to active foreground turns, and publishes survivors after turn settlement. It polls every five seconds while nonempty or after transient failure. Method-not-found disables inventory until the connection restarts. Selected stop calls terminate with the exact thread/process ID, requires `terminated: true`, then waits up to 15 seconds for absence from a refreshed roster. Lost connection/generation changes reject stale confirmations. [Inventory](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex/background-inventory.ts#L24)

AgentManager validates a per-item stop token after draining already-received session events. Inventories are memory-only; clearing ownership invalidates tokens. Protocol permissions require `workspace.read` for listing and both `workspace.write` and `hub.execute` for stop. This does not imply all providers support shell inventory equally: code has separate Claude, Codex and OpenCode v2 adapters. [Stop authorization](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/agent-manager.ts#L1421), [store](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/background-work/index.ts#L19), [permission mapping](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/authorization/operation-permissions.ts#L18)

## Startup, restart, recovery

New `CodexAppServerStartupCoordinator` serializes spawn-through-initialize per Codex state-directory key, leaving initialized clients alive concurrently. Queue timeout is 60 seconds; initialize-attempt timeout 30 seconds; at most three attempts. Only exit code 1 with the specific SQLite state-runtime initialization diagnostic is retried. Transport waits for `close` during initialize to collect final stderr. Failed children are disposed with process-tree termination; cancellation aborts queued startup and session close aborts pending initialization. This is narrow startup recovery, not automatic retry of arbitrary failed turns. [Coordinator](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex/app-server-startup.ts#L1), [transport](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex/app-server-transport.ts#L270)

Codex retryable stream errors now produce a running timeline status, resolved only by root output or final turn outcome; child activity and steering do not incorrectly signal recovery. Repeated warnings are deduplicated. Turn IDs get a random session namespace, reducing restarted-session collisions. [Stream state](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L5934)

Daemon restart recovery changes `storage.list()` to `listAll()` at startup and shutdown after storage API separation. Existing eligibility still excludes archived/internal/owned agents, clears persisted running/initializing status, and dispatches a configured recovery prompt for eligible agents when enabled. This is continuation by a fresh prompt, not restoration of an in-flight process or exact instruction pointer. [Recovery](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/restart-recovery/index.ts#L1)

Client timeline observation now supplies cursors and consults `timelineFreshnessCheck`. Host runtime changes fix stale probe comparisons/RTT inheritance and reconnect dependent routed hosts after origin recovery; healthy connection continuity still depends on client lifecycle behavior. [Timeline call site](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/app/src/contexts/session-context.tsx#L385), [runtime](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/app/src/runtime/host-runtime.ts#L1079)

## Privacy and authentication boundaries

`auth.ts` and runtime MCP capability injection have no release delta. No new voice privacy guarantee follows from the upgrade. Local speech keeps speech computation local; remote OpenAI-compatible speech sends utterance audio and spoken response text to those configured endpoints; the agent provider separately receives transcripts and tools/context. Existing voice session logs contain final transcript text and a 160-character speak preview at info level, so local-first speech is not a claim that text never reaches disk/logs. [Logging](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session/voice/voice-session.ts#L631)

The release adds plugin RPC subscriptions and binary traffic. Session authorization checks plugin binary request/response permissions and closes plugin streams when `daemon.manage` is revoked. New RPCs are individually permission mapped, including background stop. This is relevant expanded authority surface; it is not evidence of a complete security audit or of changes to the underlying relay cryptography. [Session authorization](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/session.ts#L2456)

## Targeted Linux qualification still required

Use an authorized disposable candidate VM and its own Paseo home. Do not copy existing credentials without authorization. Official Codex CLI login must be performed for that environment; combine it with local speech or explicitly approved compatible audio endpoints. Record the exact Codex executable/version, candidate commit/build, models, endpoint versions and audio format. These are proposed tests, **not executed results**:

1. **Speech configuration regression:** configure remote-compatible STT/TTS, disable local dictation, enable voice mode, leave turn detection local. Startup must initialize VAD; microphone PCM must transcribe, reach the authenticated Codex agent, invoke the actual injected `speak` tool, produce playable PCM and receive playback completion. Repeat with stock local ONNX speech. Check the documented configured base URL versus actual requested URL; a double `/v1` invalidates the test.
2. **Audio service compatibility:** exercise multipart WAV transcription, JSON text response, optional confidence/logprob behavior, arbitrary model/voice identifiers and `response_format: pcm` against the real speech service. Test separate STT and TTS origins. Ollama chat success proves none of these. Check first-audio latency because TTS buffers a full synthesis response.
3. **Real barge-in:** while a long spoken response and a long root shell command run, inject recorded user speech. Timestamp VAD, playback abort, Codex interrupt, and actual Linux process disappearance. Check parent and child PIDs externally, then verify a subsequent utterance completes. Earlier intentional background work must survive; child-agent work must follow documented separate ownership. Test overlapping turns and late process notification races. For a separate deterministic non-audio cancellation control, use stock `paseo agent stop <id> --json`, MCP `cancel_agent({agentId})`, or authenticated WebSocket `cancel_agent_request` with `agentId` and `requestId`. All reach the same cancellation command. Keep the target turn running by instructing the agent to wait repeatedly on its long Python heartbeat command; a command intentionally left after a completed turn is the preservation control, not a valid foreground-interrupt test. Inspect `provider.codex.interrupt.terminal_terminated`/`terminal_terminate_failed` logs and the actual process tree. [CLI](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/cli/src/commands/agent/stop.ts#L85), [client RPC](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/client/src/daemon-client.ts#L4334), [MCP](https://github.com/getpaseo/paseo/blob/c54bc39e7997c03a07402c09df2e825889432557/packages/server/src/server/agent/tools/paseo-tools.ts#L2215)
4. **Background inventory/stop:** create two actual distinguishable Linux background processes; allow their owning turn to finish; ensure both appear; stop one through the composer and prove only its process tree exits and its roster entry disappears. Try stale stop token after reconnect and read-only user. Older Codex lacking background APIs must degrade without false empty/success claims.
5. **Permission fidelity:** ordinary write/shell request requires appropriate approval; direct speak auto-allows only during active voice mode; wrapper tool mentioning speak does not auto-allow. Test approve, deny-with-reason, typed/spoken response, plan approval, and attempted sandbox/approval-policy change on an existing Codex session. Restart then confirm persisted options and legacy profile migration.
6. **Startup and recovery:** burst-create several Codex sessions sharing the candidate Codex home; cancel one queued startup; prove no orphan subprocess. Restart candidate daemon during a running turn with recovery enabled/disabled; verify one appropriate recovery prompt and no duplicated user action. Reconnect UI during playback and during permission wait; verify accurate status, timeline and background inventory.
7. **Privacy/authentication:** inspect candidate's own logs and endpoint access logs using benign sentinel text; verify expected transcript exposure, redact before retaining evidence. Confirm unauthenticated MCP requests fail when auth is enabled, voice MCP works with its scoped capability, read-only cannot stop tasks, and revoked plugin authority ends binary subscriptions.
